| Feature                                      | What? (1 line)                                                                  | Why?                                                                       | How? (Real-time Example)                                                                                                                                      |
| -------------------------------------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1. Security Level**                        | Decides how suspicious a visitor is.                                            | To stop known bad visitors before they reach your server.                  | A hacker from a known malicious IP visits `/login` → Cloudflare shows a challenge instead of letting them in.                                                 |
| **2. Browser Integrity Check (BIC)**         | Checks if the request comes from a legitimate browser.                          | To block fake browsers and simple attack tools.                            | A request from Chrome is allowed, but a poorly written attack script with missing browser headers is blocked.                                                 |
| **3. WAF (Web Application Firewall)**        | Inspects requests for common web attacks.                                       | To stop exploits like SQL Injection and XSS.                               | Someone sends `id=1 OR 1=1` to your login page → Cloudflare detects SQL Injection and blocks it.                                                              |
| **4. Managed Rules**                         | Ready-made security rules maintained by Cloudflare.                             | So you don't have to manually create protection for known vulnerabilities. | A new WordPress exploit starts spreading → Cloudflare's managed rule blocks it automatically.                                                                 |
| **5. Custom Rules**                          | Rules that you create based on your own requirements.                           | To protect resources using your business logic.                            | Block anyone accessing `/admin` unless they're coming from your office IP.                                                                                    |
| **6. Rate Limiting**                         | Limits how many requests a user can make.                                       | To prevent brute-force attacks and abuse.                                  | A user tries to log in 200 times in one minute → Cloudflare blocks further login attempts.                                                                    |
| **7. Bot Management / Super Bot Fight Mode** | Detects whether a visitor is a human or a bot.                                  | To stop malicious bots while allowing good bots.                           | Googlebot is allowed to index your site, but a price-scraping bot is challenged or blocked.                                                                   |
| **8. IP Access Rules**                       | Allows, blocks, or challenges specific IP addresses.                            | To control access from known IPs.                                          | Your office IP is always allowed, while a repeatedly abusive IP is permanently blocked.                                                                       |
| **9. Country Blocking**                      | Allows or blocks traffic based on country.                                      | To reduce attacks from regions where you don't do business.                | Your company only serves India, so traffic from countries you don't serve is blocked.                                                                         |
| **10. ASN Blocking**                         | Blocks traffic from a specific network provider (ASN).                          | To stop attacks coming from hosting providers or certain ISPs.             | Most attacks come from a cloud hosting provider → Block that provider's ASN instead of blocking thousands of IPs individually.                                |
| **11. DDoS Protection**                      | Protects your website from massive traffic floods.                              | To keep your website online during attacks.                                | Your server normally gets 500 visitors/minute, but an attacker sends 5 million requests → Cloudflare absorbs the attack and forwards only legitimate traffic. |
| **12. API Shield**                           | Protects APIs with extra security features.                                     | To prevent unauthorized API access and abuse.                              | Only requests from your official mobile app can access `api.example.com`; unknown clients are rejected.                                                       |
| **13. Turnstile**                            | Verifies that a visitor is human without annoying CAPTCHAs.                     | To stop spam while keeping the user experience smooth.                     | A spam bot tries to submit your contact form 1,000 times → Turnstile silently blocks it, while real users continue normally.                                  |
| **14. mTLS (Mutual TLS)**                    | Requires both the client and server to prove their identity using certificates. | To ensure only trusted devices or applications can connect.                | Only company laptops with a valid certificate can access your internal API.                                                                                   |
| **15. TLS Settings**                         | Controls how HTTPS encryption works.                                            | To keep communication secure between users and your website.               | A visitor using an outdated browser with TLS 1.0 is rejected because your site requires TLS 1.2 or higher.                                                    |
| **16. Zero Trust**                           | Lets users securely access internal resources after identity verification.      | To replace traditional VPNs with identity-based access.                    | An employee logs in with Google + MFA before accessing the company's SSH server—no public access or VPN required.                                             |
